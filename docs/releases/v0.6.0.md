# BushfireReadyGPT v0.6.0

BushfireReadyGPT `v0.6.0` hardens the boundary between trusted application
configuration, unverified user input and model-authored text. It also adds a
versioned prompt-injection red-team suite to the release evidence. The product
remains a local preparedness-planning assistant, not a live emergency service,
an autonomous decision system or an eight-agent LLM runtime.

## Highlights

- Added trusted allowlists for the six supported scenarios and recognised Focus
  concepts. Composite values such as power plus communications and water plus
  access roads expand into every required concept instead of collapsing to one.
- Added application-owned canonical coverage declarations. Raw U0 labels,
  injected aliases and model-provided declarations cannot satisfy governed
  scenario or Focus coverage checks.
- Strengthened U0 prompt-boundary neutralisation for role/control wrappers,
  delimiter variants, JSON/YAML-like payloads and long unknown tags.
- Rebuilt governed repair prompts from bounded allowlisted context. The original
  prompt, previous model response and raw U0 values are intentionally omitted.
- Excluded CommonMark code examples and semantically negated statements from
  positive scenario/Focus coverage evidence.
- Reworked absolute-safety instructions into positive risk-reduction language
  so the repair prompt does not repeatedly prime the wording it must remove. The
  deterministic safety gate remains fail closed and repair remains bounded.
- Added six versioned prompt-injection cases covering U0 role changes, governance
  removal, forged tool Markdown, delimiter/control-marker attacks and live-route
  prompt leakage.
- Extended the offline verifier to require three tracked v0.6.0 artifacts, clean
  source provenance, source-commit ancestry, shared model/index/policy identities
  and a passing red-team diagnostic gate.
- Regenerated a governed Cairns Council sample as Markdown, a 15-page PDF, a
  166-paragraph DOCX and a verified `pilot-export-v4` package.

## Boundaries And Next Step

- The eight named roles are deterministic Python component boundaries. Only
  report narrative generation and revision call the local LLM.
- Benchmark results are engineering regression evidence, not stakeholder
  validation, production accuracy or emergency-use evidence.
- No external controlled-pilot participant has been used, and no user outcome is
  inferred from automated tests.
- The next engineering priority is clearer remediation UX for drafts that remain
  blocked after bounded repair, followed by more observed Bad Case regressions.
- Authentication, database-backed multi-user operation, central monitoring and
  production deployment remain future work.
