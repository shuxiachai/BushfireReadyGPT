# BushfireReadyGPT v0.5.0

BushfireReadyGPT `v0.5.0` is a release-evidence and governance-integrity update.
It makes the current RAG, report-generation and showcase claims independently
checkable from committed artifacts while preserving the product boundary: this
is a local preparedness-planning assistant, not a live emergency-information or
autonomous decision system.

## Highlights

- Added versioned and fingerprinted governed-report quality policy
  `governed-report-v2`, including structural, safety-boundary and RAG-attribution
  rules in one canonical gate.
- Bound report rows, audit records and the governed showcase package to the same
  policy identity so stale quality results cannot be silently approved under a
  newer policy.
- Strengthened deterministic detection of live-condition, route, containment,
  warning and life-safety claims, including multiple claims and contrasting
  clauses in one sentence.
- Promoted structured-planning RAG Top-8 to an evidence-backed release gate while
  retaining free-text Top-5 as a separately reported diagnostic profile.
- Required complete per-question rows for every active RAG profile. Offline
  validation rejects missing or duplicate rows and recomputes counts, source and
  passage recall, MRR, Top-1, abstention and false-positive rate.
- Made `--summary-only` explicitly diagnostic: it always records an inactive
  release gate, even when production retrieval settings are used.
- Added start/end provenance snapshots. An active evaluation aborts before
  writing release evidence if source bytes, Git state, model identity, quality
  policy or RAG index identity changes during the run.
- Added an offline release verifier that checks the two current benchmark
  artifacts, exact source-dataset hashes, active passing gates, shared Git/RAG
  provenance, current quality policy and the governed `examples/v0.5.0` sample
  package without contacting Ollama or the network.
- Regenerated the governed Cairns sample as a verified 16-page PDF and
  203-paragraph DOCX. PDF exports now keep ordinary table rows together, switch
  oversized cells to readable record layouts and preserve list text during
  copy/search extraction.
- Retained older benchmark files as historical evidence instead of rewriting
  them under the current schema or policy.

## Reproduce And Verify

Run complete evaluations with per-question/per-scenario rows:

```powershell
poetry run python scripts\evaluate_rag.py --warmup --output output\rag-retrieval-next.json
poetry run python scripts\evaluate_report_generation.py --output output\report-generation-next.json
```

After reviewing and placing the artifacts and current showcase package in their
versioned repository paths, run the offline release gate:

```powershell
poetry run python scripts\verify_release.py
```

Use `--summary-only` only for RAG diagnostics. It intentionally cannot produce
an active release artifact.

## Boundaries And Next Step

- The benchmark results are engineering regression evidence, not stakeholder
  validation, production accuracy or emergency-use evidence.
- External controlled-pilot participants remain unavailable; no user outcome is
  inferred from automated tests.
- Grounding and retrieval similarity do not prove factual correctness, legal
  fitness or source currency.
- Authentication, database-backed multi-user operation, central monitoring,
  formal accessibility review and production deployment remain future work.

The highest-value next step remains a small controlled pilot when suitable
participants become available. Until then, keep expanding hard negatives and
Bad Case regressions without weakening the human-review and emergency-safety
boundaries.
