# BushfireReadyGPT v0.4.0

BushfireReadyGPT `v0.4.0` is an evaluation and observability release. It adds
measurable report evidence alignment, repository-safe pilot measurement and
privacy-minimised runtime diagnosis without changing the product into a live
emergency or autonomous tool-execution system.

## Highlights

- Added deterministic claim-level evidence-alignment review for model-authored
  narrative, including source recognition, lexical support, number consistency
  and Australian jurisdiction conflicts.
- Integrated evidence-alignment results into every generated/revised report
  session and the Review & Export UI while keeping the result advisory and
  explicitly subject to human source verification.
- Bound the deterministic evidence-alignment result by SHA-256 in new governed
  audit events without placing claim text into the privacy-minimised audit view.
- Extended the eight-case real-Ollama benchmark with grounding support, citation
  coverage/precision, numeric consistency and jurisdiction-conflict metrics.
- Added a strict anonymous controlled-pilot schema, aggregate calculator, edit
  effort and citation-verification measures, plus Bad Case-to-regression test
  linkage.
- Kept `docs/pilot_evaluation_template.json` empty and the project status at zero
  external participants; no user-validation result was invented.
- Added content-free per-agent/model runtime Trace records and a Readiness
  diagnostic view for success rate, P50/P95 latency, repair use, grounding review
  rate and safe failure codes.
- Kept governance audit and runtime Trace separate: the former binds governed
  report versions; the latter excludes prompts, reports, retrieval text,
  locations, audiences, identity and free text.

## Validation

- Non-E2E unit/integration/Streamlit suite: `228 passed`
- Chromium end-to-end workflow: `1 passed`
- Total automated tests: `229 passed`
- Source coverage: `85.63%` with an enforced `85%` minimum
- Ruff: passed
- Bandit: passed
- Poetry lock and installed dependency consistency: passed
- `pip-audit`: no known vulnerabilities found
- Empty pilot template evaluation: `awaiting_participants`

The committed `docs/benchmarks/report-generation-v0.4.0.json` local-Ollama run
passed all previously configured release gates across the six product scenarios,
live-request refusal and no-RAG degradation. It averaged `27.74 seconds` and one
of eight cases required structural repair.

The new diagnostic grounding baseline measured:

| Metric | Result |
| --- | ---: |
| Average lexical evidence support | 0.9540 |
| Average sentence-level citation coverage | 0.2311 |
| Average cited-source precision | 1.0000 |
| Average numeric consistency | 0.9583 |
| Jurisdiction conflicts | 0 |
| Reports requiring grounding review | 8 / 8 |

These grounding metrics are not enforced by the aggregate benchmark `passed`
field in this release. The result file states
`grounding_release_gate_enforced: false`. The baseline exposes insufficient
sentence-level source attribution and provides a measured target for the next
report-template iteration; it is not a factual-accuracy claim.

## Boundaries And Next Step

- External stakeholder sessions still have not run.
- The grounding evaluator is a deterministic lexical heuristic, not semantic
  entailment, legal review or factual proof.
- Runtime Trace is local single-instance diagnosis, not central production
  monitoring, distributed tracing, alerting or retention-controlled storage.
- Authentication, signed approval, database-backed multi-user operation,
  container deployment, accessibility review and formal licence/legal decisions
  remain future work.

The highest-value next action remains the controlled 3-5 person pilot. In
parallel, use the measured `0.2311` sentence-level citation-coverage baseline to
improve inline source attribution, then promote the grounding metric to a release
gate only after the heuristic and target are calibrated against human review.
