# 项目审计与修复记录（2026-09-10）

本轮针对报告治理、访问控制、数据证据、检索分块和 Windows 启动流程进行代码复核及可复现回归。下列问题均有代码或测试证据；记录的是可触发的缺陷及其影响边界，不代表已在线上被利用，也不构成完整安全认证。

## 已确认问题与修复

| # | 问题与影响边界 | 本轮修复 | 专项回归 |
| --- | --- | --- | --- |
| 1 | **修订快照未完整绑定父报告。** 下层审计接口原可接受已变更的规划输入、分析结果或地图选择，仍沿用父报告的修订链。 | 在父报告锁内、写入修订占位前，校验输入、分析及区域快照与父报告一致；拒绝畸形快照。措辞修订和模型变更仍可进行，规划条件改变必须重新分析生成。 | [修订边界测试](../tests/test_governed_revision_boundaries.py)：三类快照篡改、异常类型、合法修订，以及失败后不消耗修订名额。 |
| 2 | **畸形审核项 ID 导致异常。** 列表、字典等不可哈希 ID 会使审核完整性检查抛出 `TypeError`，而非安全地拒绝审核。 | 先确认 ID 为字符串，再检查合法集合；工作流返回未完成审核提示，审计入口拒绝无效数据。 | [审核输入测试](../tests/test_governed_review_input_boundaries.py)：非字符串 ID、工作流错误反馈及有效清单。 |
| 3 | **签审成功后预览与下载仍可能是旧草稿。** 页面较早渲染的内容不会随同轮后续状态更新而自动替换，直接下载也未必触发重跑。 | 成功签审后完整重跑页面；一次性结果提示跨重跑保留，预览、侧栏和下载重新绑定当前签审版本。不能撤回此前已交付浏览器的字节。 | [工作流测试](../tests/test_streamlit_workflow.py)、[浏览器回归](../tests/test_browser_e2e.py)：普通下载与受口令保护的 Blob 下载均核对签审后内容。 |
| 4 | **云端导出/保存错误可能暴露服务器细节。** 部分页面直接显示异常文本，可能向当前访问者泄漏本机路径等内部诊断信息。 | PDF、DOCX、报告保存和试点包错误统一经过安全诊断处理；云端收敛提示，本地保留排障信息。 | [云端 UI 隐私测试](../tests/test_cloud_ui_privacy.py)：各错误入口及云端/本地模式对照。 |
| 5 | **相同访问口令与管理员口令可绕过格式相等检查。** 明文与哈希混合存储、或两个不同盐的哈希，不能仅通过配置对象相等判断密码是否相同。 | 明文/哈希组合在配置检查时比对；不同盐哈希在管理员登录验证成功后，用本次输入核验访问口令并拒绝重复密码，不签发管理员会话。无法在未知明文时预先推断两个独立哈希对应相同密码。 | [鉴权测试](../tests/test_deployment_access.py)：两种混合存储方向、不同盐相同密码，以及既有鉴权回归。 |
| 6 | **锁记录读取存在大小检查与读取之间的窗口。** 文件在检查后增长可绕过读取上限；小体积深层 JSON 也可能触发未处理的递归异常。 | 二进制读取最多上限加一字节，超限直接拒绝；损坏编码、JSON 和递归异常视为无效记录。原有持锁、存活判断及恢复语义不变。 | [文件锁测试](../tests/test_file_lock.py)：检查后增长的记录、深层损坏 JSON 和锁恢复。 |
| 7 | **缺失交通指标会吞掉有效高龄指标。** 两项指标共用转换异常处理，一项无效会把另一项有效值一起清零。 | 独立解析两项百分比，拒绝布尔、非有限值和超出范围值；保留另一项有效提示，区分真实零值与缺失值。 | [分析证据一致性测试](../tests/test_analysis_evidence_consistency.py)：两种缺失方向、异常数值与合法零值。 |
| 8 | **带重叠的长段落分块可能超过 `max_words`。** 原有长段落切分未完整计入前块带入的重叠词。 | 分块统一计入重叠预算，确保每块不超上限且持续加入新词，保持顺序、确定性与来源隔离。 | [分析证据一致性测试](../tests/test_analysis_evidence_consistency.py)：长段落与边界组合、不同重叠量、原文重建及跨来源隔离。 |
| 9 | **地图缓存可能复用过期验证，证据清单缺少边界与 sidecar。** 文件被替换或保留大小/修改时间地改变后，仅依赖旧 UI 缓存可能误判可信；此情形以本地文件变化为前提，不意味着远程访问者拥有文件写权限。 | 报告生成独立要求内容核验，显示缓存增加路径和文件身份信息；全国 SA2 数据来源指纹同时纳入统计表、边界及 `sa2_map_bundle.json`。内容哈希绑定的小型结构缓存减少重复解析，性能与首次加载限制见下节。 | [地图验证测试](../tests/test_optional_map_verification_cache.py)：过期 UI 缓存、同大小/时间篡改、路径隔离、并发、结构缓存和文件切换。 |
| 10 | **FastEmbed 启动错误依赖 Ollama，且缺少 CPU 准备检查。** 选择 CPU 嵌入时仍可能启动或检查不必要的 Ollama；缺失可选依赖或模型身份文件时反馈过晚。 | 按报告与嵌入各自的提供方决定是否需要 Ollama；CPU 模式在资料/模型下载前，离线检查依赖与已准备模型身份，未就绪即给出手动准备提示。默认本地 Ollama 路径保留。 | [启动逻辑测试](../tests/test_windows_launcher.py)、[CPU 预检测试](../tests/test_windows_cpu_preflight.py)：提供方组合、无下载预检、失败顺序及跳过路径。 |

这些修复不将共享口令演示升级为生产级多租户权限系统。CPU 模式仍需使用者手动安装可选依赖并明确准备模型；本轮未实现 Windows CPU 环境的一键安装或自动下载。

## 大型地图内容校验与内存边界

全国地图文件为 186.29 MB，包含 2,473 个区域。每次 fresh 核验均重新计算统计表、边界和配套清单的真实内容哈希；只有内容完全相同且此前成功验证的结果才复用。缓存至多 8 组小型结果，不保留大型 GeoJSON 对象；首次解析串行执行，避免同进程并发叠加峰值。

未命中时，将实际解析字节与本次内容身份绑定；命中后仍再次核对文件内容。增加 10 项内容缓存回归，覆盖保留大小/修改时间的篡改、换入新内容、异常不入缓存、并发、上限、解析时切换又还原及返回前变化。交叉审查还复现并修复了“开始时缺少清单、解析期间清单出现”的升级旁路：该次调用不得升级为已验证，必须等待稳定文件重试。相关地图/数据回归共 54 项通过。

同一 Windows 新进程上的只读实测（不修改原始文件）：

| 校验阶段 | fresh 耗时 | 含分析前后来源哈希 | 内存观测 |
| --- | --- | --- | --- |
| 首次新内容 | 3.032 秒 | 3.303 秒 | 系统记录的生命周期峰值工作集 920.94 MiB |
| 第二次相同内容 | 0.255 秒 | 0.522 秒 | 本阶段每 5 ms 采样，观测到的最高工作集 35.52 MiB |

两次均通过结构与哈希校验，前后来源指纹一致。第二次的采样值不是操作系统精确峰值，也不能与不可重置的生命周期峰值混淆。首次新地图仍完整解析 JSON，约 921 MiB 的开销尚未消除；小内存部署仍需单独做冷启动/地图容量测试。这不是流式低内存解析实现，也不是 Railway 性能测量。
